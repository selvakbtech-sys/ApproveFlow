Section 01
System Overview

1.1 Purpose & Scope

ApproveFlow is a multi-level approval workflow management system built for organizations with multiple locations and departments. It digitizes the request-approval cycle — eliminating email chains and manual follow-ups — by routing every request through a configurable, sequential approval chain with full audit trail.

This SOP covers all aspects of system operation for end-users (submitters), approvers, and system administrators.

1.2 System Architecture

🖥️ Technology Stack

  • Framework: ASP.NET Core 8 MVC
  • Database: SQL Server with Entity Framework Core 8
  • UI: Bootstrap 5 (responsive)
  • Auth: Cookie-based, 8-hour session
  • Passwords: BCrypt hashed
  • Timezone: IST (India Standard Time)

📲 Integration Channels

  • In-app: Notification center with unread badge
  • WhatsApp: Meta Business API v19.0
  • Template messages with interactive buttons
  • File attachments via Meta Media API
  • Aging reminders via background service

Section 02
User Roles & Permissions

2.1 Role Structure

Every user is assigned exactly one Role. Roles are fully configurable by the administrator. A role carries a set of per-screen permissions that govern what the user can see and do in the system.

⚠️
Approval Rights Guard The CanApprove permission cannot be removed from a role that is currently referenced in an active Workflow Definition. You must deactivate or update the workflow first.

2.2 Screen-Level Permissions

Each role can be granted individual permissions per screen. All permissions are checked at runtime from the user's login cookie claims.

PermissionWhat It Allows
CanViewAccess the screen / see records
CanCreateCreate new records (requests, users, workflows, etc.)
CanEditModify existing records
CanApproveAppear as an available approver in Workflow Definitions; take approval actions
CanDeleteRemove records (with integrity checks)

Section 03
Request Lifecycle

3.1 Creating a Request

1
Navigate to New Request

Click New Request in the navigation. Requires CanCreate permission on the Requests screen.

2
Fill in Request Details

Provide: Title, Request Type, Department, Location, Priority (Low / Medium / High / Critical), optional Amount, Description, and Notes.

3
Preview Workflow

The form automatically displays the matched approval workflow via an AJAX call. Verify the correct approvers are shown before submitting.

4
Attach Documents (Optional)

Upload supporting files. Supported formats and size limits are configured in system settings (MaxFileUploadMB).

5
Save as Draft or Submit

Save Draft — stores the request without starting approval. Submit — assigns a REQ-YYYY-NNNN number, triggers workflow matching, and notifies L1 approver via in-app + WhatsApp.

Section 04
Workflow Configuration

4.1 Workflow Matching Algorithm

When a request is submitted, the system finds the best-matching active workflow using a specificity scoring algorithm. More specific criteria earn higher scores. The workflow with the highest total score wins.

Criterion MatchedPointsNotes
Location match+2Workflow has a specific Location set
Department match+2Workflow has a specific Department set
Request Type match+2Workflow has a specific Request Type set
Priority match+1Workflow has a specific Priority set
(No criteria — default)0Catch-all workflow with no restrictions
💡
Best Practice Always create a default workflow (all fields blank) as a fallback. Then create specific workflows for high-priority or department-specific request types that need different approvers.

4.2 Setting Up a Workflow — Step by Step

1
Go to Workflow Definition

Navigate to Settings → Workflow Definition. Requires Admin CanCreate permission.

2
Set Matching Criteria

Choose any combination of Location, Department, Request Type, and Priority. Leave fields blank to match all values for that criterion.

3
Add Approval Steps (Levels)

Add 1–3 approval levels. For each level, either select a specific approver user or check Auto-assign Department Manager. The same user cannot appear at multiple levels.

4
Set Status and Save

Toggle the workflow Active to make it eligible for matching. Inactive workflows are ignored during matching.

4.3 Workflow Business Rules

✅ Allowed

  • 1, 2, or 3 approval levels
  • Mix of named approvers and auto-assigned managers
  • Multiple workflows with overlapping criteria (scoring resolves ties)
  • Deactivating a workflow (existing requests are unaffected)

❌ Not Allowed

  • More than 3 approval levels
  • Same user assigned to multiple steps in one workflow
  • Deleting a workflow referenced by existing requests
  • Approver without CanApprove permission on their role
⚠️
No Workflow Found? If no active workflow matches a submitted request, the submission will fail with an error. Ensure a default catch-all workflow is always active.

Section 05
Approval Chain

5.1 Sequential Approval Flow

Approvals proceed strictly in sequence. Level 1 (L1) must complete their action before Level 2 (L2) is activated and notified. A higher level approver cannot act on a request before their turn.

1
Submit
Workflow matched, L1 set to pending, L2+ set to waiting
›
2
L1 Acts
L1 approves → L2 activated and notified
›
3
L2 Acts
L2 approves → L3 activated (if exists)
›
4
Final Approval
All levels approved → Status = Approved

5.2 Approver Actions

An active approver can take one of three actions on the Request Detail page or via WhatsApp:

ActionEffectNotification Sent
Approve Step marked approved. Next level activated, or request fully approved if last step. Next approver (if any) + Requestor on final approval
Reject Request immediately moves to Rejected. Remaining steps cancelled. Requestor — rejection with comment
Clarification Request pauses at current level. Moved to Clarification Needed. Current step level unchanged. Requestor — clarification request with comment
📝
Comments Are Mandatory for Reject & Clarification Approvers must provide a comment when rejecting or requesting clarification. Approval comments are optional but recommended.

5.3 Clarification Flow

When an approver requests clarification, the request does not reset — it pauses at the same approval level.

1
Approver: Clarification
Comment added. Request → Clarification Needed
›
2
Requestor Notified
In-app + WhatsApp notification with question
›
3
Requestor Updates
Edits description/notes/documents and resubmits
›
4
Resume at Same Level
Approver receives notification to continue review

5.4 Per-Step Audit Trail

Every action is permanently logged in the Request Action Log with:

  • Actor (who acted), Timestamp (IST), Step Level, Action Type
  • Comment text, Previous status → New status
  • Viewable on the Request Detail page under the History tab

Section 06
Dashboard

The Dashboard is the landing page after login. It displays request statistics and quick-access tables. The data shown depends on the user's role and permissions.

6.1 My Requests Tab

👤
Data Scope: Requests created by the currently logged-in user only.
  • KPI cards show counts for each status (Draft, Pending, Approved, Rejected, Clarification)
  • Table lists the same requests as the KPI cards — no filter mismatch
  • Clicking a KPI card filters the table to that status
  • Quick-access buttons: View, Edit (if Draft/Clarification), Delete (if Draft)

6.2 My Approvals Tab

✅
Data Scope: Requests where the logged-in user is the active approver at the current step level.
  • Only shows requests awaiting this user's action (status = pending at their level)
  • KPI card shows count of pending approvals — matches the notification bell count
  • Quick-action: Approve / Reject / Clarification directly from the table row
  • Visible only if the user has CanApprove permission

6.3 My Territory Tab

🗺️
Data Scope: All requests belonging to the user's assigned locations and departments.
  • Provides visibility across an entire location or department without approval rights
  • Read-only — no action buttons
  • Users are assigned to locations/departments via User Management

6.4 Admin Dashboard

Users with the Admin role see an expanded dashboard with organization-wide data:

📈 KPI Cards

  • Total requests (all users, all statuses)
  • Pending approvals across all departments
  • Approved this month
  • Rejected this month
  • Requests awaiting clarification

📊 Charts Available

  • Requests by Type (pie/bar)
  • Requests by Priority
  • Requests by Location
  • Requests by Department
  • Monthly trend (12-month bar chart)
🔒
Dashboard Validation Rule KPI card counts and the detail table below always use identical filters. A count of 5 in a KPI card means exactly 5 rows will appear in the table when that filter is applied. This is enforced at the service layer.

Section 07
Notifications

7.1 In-App Notifications

The notification bell (🔔) in the top navigation bar shows the count of unread notifications. Clicking it opens the Notifications center.

Notification TypeTriggered WhenRecipient
action_requiredA request is submitted or resubmitted and awaits this user's approvalCurrent Level Approver
approvedAll approval levels completed — request fully approvedRequestor
rejectedAn approver rejects the requestRequestor
clarificationAn approver sends a clarification requestRequestor
progressIntermediate level approved, next approver activatedNext Approver

Notifications can be managed from the Notifications page:

  • All tab — complete notification history
  • Unread tab — notifications not yet viewed
  • Pending tab — action-required notifications only
  • Mark as Read / Mark All Read — clears the badge count
📌
Count Consistency Rule The notification bell count and the "My Approvals" KPI card count are always equal for a given user. If you see 3 pending approvals on the dashboard, the bell will also show 3.

7.2 WhatsApp Notifications

Approvers with a registered WhatsApp number receive rich notifications with interactive buttons directly in WhatsApp.

🤖 ApproveFlow
New Approval Request
📋 REQ-2026-0042 — Office Equipment Purchase
👤 Submitted by: Ravi Kumar
📂 Type: Purchase | 🏢 Dept: IT
⚡ Priority: High | 💰 Amount: ₹45,000

Please review and take action:
✅ APPROVE ❌ REJECT 💬 CLARIFICATION

WhatsApp Button Flow

  • APPROVE button → Request approved immediately. Confirmation message sent.
  • REJECT button → Bot prompts for a rejection comment. User replies with text → request rejected.
  • CLARIFICATION button → Bot prompts for the clarification question. User replies with text → clarification sent to requestor.
📱
WhatsApp Number Required Approvers must have a WhatsApp number registered in their user profile to receive WhatsApp notifications. In-app notifications are always sent regardless.

7.3 Aging Reminders

A daily background service runs at a configurable IST hour (default: 9:00 AM) and sends WhatsApp reminders to approvers for any requests in Pending Approval status that have been waiting beyond a defined threshold. This ensures no request is silently forgotten.

Section 08
System Administration

8.1 Master Data Management

Master data defines the building blocks of the system. All master data requires Admin permissions.

Master EntityFieldsUsed ByNotes
Locations Name, Code (unique), IsActive Requests, Workflows, User Territory Cannot delete if referenced by users or requests
Departments Name, Code (unique), IsActive Requests, Workflows, User Territory Cannot delete if referenced by users or requests
Request Types Name, Code (unique), IsActive Requests, Workflows Cannot delete if referenced by existing requests
⚠️
Deactivate vs Delete Prefer deactivating a master record over deleting it. Inactive records are hidden from new request forms but historical records remain intact. Deletion is blocked by stored procedures if any references exist.

8.2 User Management

1
Create User

Set Full Name, Email (unique), Role, WhatsApp Number, and initial password. User receives a Must Change Password flag forcing a reset on first login.

2
Assign Territory

Assign the user to one or more Locations and Departments. This determines what appears in their "My Territory" dashboard tab.

3
Toggle Status

Deactivated users cannot log in. Their historical records and approvals are preserved. Use Toggle Status to suspend access without deleting the account.

4
Reset Password

Admin can reset any user's password. The user will be forced to change it on next login. Passwords are stored as BCrypt hashes — never in plain text.
